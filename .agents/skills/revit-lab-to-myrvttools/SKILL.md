# Перенос команды из EOM Lab в MyRvtTools

## Найди исходник и назначение

1. Прочитай применимые `AGENTS.md` лаборатории и MyRvtTools. В типичном рабочем каталоге лаборатория находится в `EOM-RevitLab/EOM-RevitLab.extension/EOM Lab.tab`. Расширение MyRvtTools находится в соседних рабочих копиях `main` и `test`. Уточни пути и активные ветки по фактической структуре и `git status`.
2. Найди исходный `*.pushbutton` по заголовку в `bundle.yaml`, имени папки и назначению команды. Используй актуальную версию из загружаемого расширения EOM Lab или версию, которую указал пользователь. Проверь версию и известные ограничения по паспорту, если он есть.
3. Сверь исходник с целевой командой и текущей веткой на GitHub. Локальные рабочие копии и ссылки `origin/*` могут отставать. Проверь код точки входа, модули, XAML, ресурсы и иконки. Учитывай эквивалентные переименования пакета и разницу в окончаниях строк. Если рабочие файлы уже совпадают, укажи существующую версию и путь кнопки. Создавай коммит только для реального изменения.

## Перенеси и проверь

1. Для новой кнопки выбери подходящую существующую панель и добавь имя папки без суффикса `.pushbutton` в `layout:` файла `bundle.yaml` панели, если порядок задан. Для обновления сохрани панель, имя существующей кнопки и её место, если пользователь не указал другое. Сохрани предыдущую версию вне загружаемого дерева перед заменой файлов.
2. Переноси полный комплект команды. Проверь `script.py`, `bundle.yaml`, локальные импорты, XAML и подключаемые словари стилей, иконки, шаблоны и лицензии. Перенеси недостающий общий код в соответствии со структурой проекта. Сохрани совместимость с установленными Revit и pyRevit, существующие профили, ключи настроек и идентификаторы, записываемые в модель. Для пакетов с риском коллизии проверь имена импортов и пути ресурсов.
3. Ограничь diff переносимой командой и необходимой регистрацией. Сохрани рабочие правки пользователя и исходник EOM Lab, если его удаление не запрошено. Проверь структуру, синтаксис, импорты, XAML и существующие тесты там, где они применимы. Отдельно установи статус проверки в Revit. Принимай подтверждение пользователя, если проверенная команда и выпускаемая версия совпадают. Для выпуска в `main` соблюдай правила проверки текущего проекта.

## Опубликуй и сверь выпуск

1. Для выпуска коллегам работай с `poperechnyi98/EOM-RevitTools` через подключённый GitHub. Проверь доступ, актуальные вершины `dev` и `main` и состав diff. Отправь в `dev` только согласованные изменения. Если публикуешь через GitHub API, используй актуальное дерево в качестве основы, передавай бинарные ресурсы без перекодирования и проверь итоговые хеши. Обновляй ветки без force-push, сверяя ожидаемую вершину после изменений.
2. Перенеси в `main` только проверенный и согласованный diff. Если `dev` содержит другие изменения, выдели выпуск этой команды в отдельную ветку от текущего `main`. При отсутствии подтверждения проверки в Revit оставь выпуск в рабочей ветке и сообщи, какого подтверждения ждёшь. Если пользователь просит изменения только локально, ограничься локальной рабочей копией.
3. После публикации прочитай файлы команды и раскладку панели из целевой ветки на GitHub. Укажи ссылку на опубликованный коммит или PR, панель и кнопку, статус проверки. Для коллег на `main` укажи **MyRvtTools → Сервис → Обновить**. Если окно обновления показывает старый коммит, сначала сравни этот SHA с текущим `main` и выясни, какая копия расширения загружена.
